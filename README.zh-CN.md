# idea-review

一个 Claude skill：把一个粗糙的想法，变成一份**诚实的判断**和一份**可执行的开发方案**。

[English](README.md)

---

## 为什么做这个

让任意一个 AI 助手评估你的想法，你会收获一整墙的鼓励。它会替你找到市场、编出一个 TAM、罗列十个功能，然后告诉你「前景广阔」。而这恰恰是你在决定要不要投进去三个月人生的那一刻，最没有用的东西。

`idea-review` 的默认行为是反过来的。它被明确要求：

- **先调研，后判断。** 市场结论、竞品名称和定价必须来自当次会话的真实搜索，不能来自模型记忆。
- **主动找反面证据。** 会刻意去搜 "why did X fail"、"X alternative"，而不是只捞支持结论的材料。
- **坏消息放最前面。** 如果已经存在成熟的免费或开源替代品，这句话出现在第一段，而不是埋进第三节。
- **敢说不。** 「不建议做」和「改成一个小得多的东西」是一等公民结论，给出时不道歉、不加缓冲垫。
- **区分事实与推测。** 每个市场数字带来源链接；没有来源就写「无可靠公开数据」，不编。

## 你会拿到什么

两个 Markdown 文件：

| 文件 | 内容 |
|---|---|
| `<短名>-可行性分析.md` | 想法重述、调研发现、7 维度评分卡、一句话结论、「这个想法最可能死在哪里」，以及（若结论不是「不建议做」）技术方案 |
| `<短名>-开发任务清单.md` | 按依赖排序的任务，验收标准可机器验证，单个粒度半天到两天，可直接交给 coding agent |

## 安装

**Claude Code** —— 个人级 skill（所有项目可用）：

```bash
git clone https://github.com/sp1128/idea-review.git ~/.claude/skills/idea-review
```

或只作用于单个项目：

```bash
git clone https://github.com/sp1128/idea-review.git .claude/skills/idea-review
```

**Claude 桌面端 / Cowork** —— 打开 `SKILL.md`，复制内容，让 Claude 保存为 skill。

在 Claude Code 里用 `/skills` 确认加载成功。

### 中文输出

仓库根目录的 `SKILL.md` 是英文版。要让它输出中文报告，用中文版覆盖：

```bash
cp i18n/SKILL.zh-CN.md SKILL.md
```

skill 的指令语言决定报告语言，所以这一步是必须的——只在对话里说中文不够。

## 怎么用

直接描述想法就行，skill 会自己触发：

```
我想做一个给独立开发者用的、自动生成变更日志的 CLI
```

```
做一个把播客转成带说话人标注的可搜索文字稿的工具，值得做吗
```

它最多问一轮澄清问题——给谁用、愿意投多少时间、有没有硬约束——然后调研、评分、成文。

## 工作流程

```
澄清（≤3 个问题）
   ↓
用四行重述想法  ← 有一行填不出来，说明想法还没成形
   ↓
并行调研  ← 竞品 · 开源替代 · 关键技术与单位成本
   ↓        需求侧信号 · 合规红线
评分卡（7 维度，1–5 分）
   ↓
结论：值得做 / 有条件做 / 缩小范围做 / 不建议做
   ↓
技术方案（架构、选型、难点、MVP 边界、里程碑）
   ↓
交给 coding agent 的任务清单
```

### 评分卡

| 维度 | 在看什么 |
|---|---|
| 痛点强度 | 是"忍不了"还是"有了也不错"。有人为此付过钱吗 |
| 市场规模 | 能触达的用户量级；小众不等于不能做，但要说清天花板 |
| 差异化与壁垒 | 大厂/现有玩家一周能不能抄掉 |
| 技术可行性 | 最不确定的技术点是什么，有没有现成方案兜底 |
| 成本与工作量 | 人月估算 + 持续运营成本（服务器、API、审核） |
| 变现路径 | 谁付钱、付多少、什么时候付 |
| 风险 | 合规、平台依赖、法律、单点依赖 |

所有维度都打 4 分的评分卡等于没有信息量。skill 被明确要求：该给 2 分就给 2 分。

### 任务长什么样

```markdown
### T-03 用户认证
**目标**：邮箱注册/登录，会话持久化
**验收标准**：
- [ ] 未登录访问 /dashboard 重定向到 /login
- [ ] 注册后自动登录，刷新页面会话保持
- [ ] 密码错误返回 401 且不泄露账号是否存在
**依赖**：T-01（项目脚手架）、T-02（数据库 schema）
**涉及**：src/auth/、middleware/session.ts
**预估**：0.5 天
```

验收标准必须可机器验证或可点击验证。「实现良好的用户体验」不算验收标准。

## 定制

skill 就是一个 Markdown 文件，直接改。常见改法：

- **加维度**：合规负担、招人难度、生态锁定
- **换调研源**：把 Reddit / HN 换成你目标市场真正活跃的社区
- **锁定技术栈**：加一句「优先 Go + Postgres」，技术方案就不会每次换一门语言
- **收紧 MVP 上限**：默认超过 15 个任务就砍，你的 v1 老是膨胀的话可以调低

## 参与贡献

欢迎 Issue 和 PR。最有价值的贡献是**它判断错了的案例**——它吹捧了一个本不该做的想法，或者跳过了某个调研步骤。把想法原文和它的输出贴出来，这是改进指令最有效的材料。
